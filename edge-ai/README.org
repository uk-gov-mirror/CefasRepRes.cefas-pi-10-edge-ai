#+TITLE: Plankton Imager Edge-AI

* Introduction

This directory contains the Python code for the Plankton Imager Edge
AI system, sponsored by the Turing Institute.



Features include

- UDP listener that receives images from the PI10 instrument.

- Two classifiers - a ResNet50 and a ResNet18 that can discriminate
  copepod, non-copepod and detritus.

- Ability to store images in bin files (faster than writing individual
  images).

- Sending of summary data to Azure storage for use by a digital
  dashboard.

- Display of labelled images

- Parsing GPS data, including an interactive Plotly HTML report with datetime filtering

- The Data viewer tab can download processed =summary.json= files in
  parallel from =ml-prediction-results=, match them to raw TAR locations, and
  filter the exported report by model, requested sample percentage, size
  threshold in pixels (=inf= means not applied), and raw
  container. Requested sample percentages are normalized and compared numerically,
  so values such as =1= and =1.0= match the same dropdown selection.
  Class counts remain separate for each model.
  Before matching locations, summaries with the same raw container, TAR,
  model, =sample_ratio_requested= (within-TAR sampling),
  =sample_percent_requested=, and =size_threshold_px= are deduplicated: the
  newest =generated_utc= is kept and a warning identifies each oldest run
  dropped before merge.
  Equal timestamps use the summary blob name as a deterministic tie-breaker.
  Missing or invalid timestamps are treated as oldest with an additional warning.
  Summaries without a size threshold are treated as =inf= (unfiltered).

- Optionally restrict processed-summary downloads by opening "Show GPS plot",
  enabling "From datetime" and/or "To datetime", and applying the filter before
  "Load processed summaries". Only the visible TARs' =per_tar= summary paths
  are downloaded across all runs; filtering uses the first TIFF capture time,
  not the run timestamp. Bounds are inclusive; use 00:00:00 to 23:59:59 for a
  whole day. Locations without capture times and nonmatching or missing
  =per_tar= paths are excluded. Clearing the datetime filter restores
  unrestricted loading. The applied datetime range survives result refreshes.
  Hover text is excluded from layout calculations so it cannot resize the map.

- In the native GPS plot, click a TAR marker or use "Selected TAR images".
  Apply model, sampling and size filters until exactly one associated
  =summary.json= remains, choose a "Predicted label", then click "Get images".
  The paired =predictions.json= supplies =blob_member_uri= entries whose
  =predicted_label= matches; only those TIFF members are loaded from the TAR.
  The gallery supports cancellation and full-size viewing by double-clicking.
  Its temporary images are deleted when it closes. Use the TAR dropdown to
  distinguish archives with identical GPS coordinates.

- After "Scan TARs for first TIFF GPS" completes, Data viewer unlocks a
  dropdown of all polled TARs, including those without GPS. Select one, an
  output directory, up to N mosaics, and a width X and height Y in pixels,
  then click "Export mosaics". Images are packed in stream order onto white
  X-by-Y PNG canvases, preserving aspect ratio and shrinking only images
  larger than a canvas. Each export creates a new subdirectory without
  overwriting earlier exports. The last canvas may be partially filled;
  fewer than N mosaics are written if the TAR ends first.
  "Skip every Sth" drops images S, 2S, 3S, etc. before decoding (0 keeps all,
  1 skips all). Skipping avoids decoding, not the sequential TAR download.
  The log reports each saved mosaic and the final image ordinal, included
  and skipped counts, last member name, and TAR byte position. Uncompressed
  TARs also show a percentage of the blob; compressed TARs show only an
  uncompressed byte position. Filling the final canvas can require reading
  one image ahead, which is counted as reached but not included. "Stop"
  retains completed mosaics and saves the current partial canvas.

- Extraction of morphological measurements

- In the inference Application tab, check "Prioritise smallest TAR files first"
  before running to process selected archives from smallest to largest blob size.
  Leave it unchecked to preserve CSV order. Parallel streams start in this order;
  completion order can vary.

- Before running the inference Application, optionally use "Select classes to
  retain locally" to load the potential classes from the selected =.pt= model
  and choose which predicted classes to keep. Matching original images are
  written under the run folder's =retained_classes/<class>/<tar>/<member>=
  hierarchy; leave the selection empty to save no additional image files.
  Per-TAR and run summaries record the selected classes and retained image
  count.

- When generating the inference TAR CSV, the within-TAR sampling prompt is
  followed by a minimum image size threshold. Use =inf= (the default) to
  disable size filtering, or a positive integer pixel count. Edit
  =size_threshold_px= per TAR in the CSV and reload it to change individual
  selections. Older CSVs without this column remain unfiltered.
  An image is skipped if its original width OR height is below the threshold;
  equality is retained. Dimensions are read lazily from image metadata before
  resizing, normalising, or creating an inference tensor.
  =summary.json= records the threshold and =size_filtered_image_count=, and
  each =predictions.json= record logs =size_threshold_px= alongside the model
  and sampling choice. Disabled thresholds are stored as the JSON string
  ="inf"=, not a non-standard JSON Infinity value.
  The day runner also accepts =--size-threshold-px= (or =SIZE_THRESHOLD_PX=);
  the =tar-inference= workflow exposes the same input.
  Resume skips an existing TAR only when its saved size threshold matches the
  requested one; legacy summaries count as unfiltered.





* Installation: Linux

** Install Python environment, this has been tested on 3.8.10 (linux) and 3.11.0 (windows)

Linux tested using this version of python:
wget https://www.python.org/ftp/python/3.8.10/Python-3.8.10.tar.xz


To install required packages. Linux:

#+begin_src bash
  cd ~/git/rapid-plankton/edge-ai
  python3 -m venv env
  source env/bin/activate
  python3 -m pip install --upgrade pip
  python3 -m pip install -r requirements.txt
  
  It is likely at this point that you get an error, as the version of jetpack you are using has a specific version of torch in the requirements-jetson.txt, I would suggest we move towards using jetson containers for the correct version https://github.com/dusty-nv/jetson-containers/tree/master
  
  A possibly unrelated error after updating the jetson... you may also have to sudo apt install libopenblas-dev -y
  
#+end_src

If using azure command line interface tools (easy to install on jetson):

#+begin_src bash
  curl -sL https://aka.ms/InstallAzureCLIDeb | sudo bash
#+end_src


To activate in Linux:

Subsequent activation (required every time). Linux:

#+begin_src bash
  cd ~/git/rapid-plankton/edge-ai
  source env/bin/activate
#+end_src


Once in (env), on Linux test with:

#+begin_src bash
  ./edge-ai.py --help

* Usage
** Help

Features are switched on or off and configured by means of command
line arguments. For more informations see:

#+begin_src bash
  ./edge-ai.py --help
#+end_src

If you want to see progress, then use =--verbose= to log to the
terminal.

If things are going badly and you need more debug information, then
set =--loglevel DEBUG=.

Verbose diagnostics for the dashboard sending path are enabled when
=--verbose=, =--debug=, or =--loglevel DEBUG= is used.  These entries
are prefixed with =[send-diagnostics]= in the logs.

In general, the more things you switch on, the lower the throughput.

Stopping the app is currently bug - try pressing =q=. If that doesn't
work, type =CTRL-C=.



* Here are some typical use cases

** Fast storage of images

Plug in your external hard drive and change directory to where you
want to store your data. Run this command:

#+begin_src
  ./edge-ai.py --store
#+end_src

Images are stored in =bin= files. these can be split up later into
tiff file using the supplied =split_bin.py= script.

** Local classification

Run the classifier. Use background correction.

#+begin_src
  ./edge-ai.py --classify --verbose  --background-correction
#+end_src

Counts per minute are logged to a file.
